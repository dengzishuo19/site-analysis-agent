# 派工单 002：周边设施检索与统计（纯代码，不含大模型）

状态：已执行，待用户在地图上抽查验收

## 背景
这是第一个真正的业务功能。核心设计决策：**计数和距离由代码计算，不交给大模型**，因为大模型数数不可靠，而 PRD 要求简报里每个数字都能对上统计表。本单只产出可靠的统计数据；写简报是下一张单（003）。

## 要做什么
1. 在 `lib/amap.ts` 增加周边检索函数：以经纬度为中心、半径 1000 m，按类别检索设施（高德“周边搜索”接口）。
2. 六个类别，每类用高德官方 POI 分类编码检索（执行方必须对照高德 POI 分类编码表核实编码，不许凭记忆）：
   - 交通：地铁站、公交站（分开统计）
   - 教育：学校（含大学、中小学）
   - 医疗：医院
   - 商业：购物、餐饮
   - 公园绿地：公园广场
   - 工业：只含“工厂”和“产业园区”两个子类；**不含“公司”**（会把写字楼里的办公公司全部算入，数量失真）
   - 注意：POI 不等于用地性质，工业类结果为 0 是正常情况，输出中如实返回 `count=0`，不许当作错误处理
3. 新建 `lib/stats.ts`，输入某地址，输出统一结构：
   ```
   { center: {address,lng,lat}, radius: 1000,
     categories: [{ key, label, count, nearest: {name, distanceM} | null,
                    items: [{name, distanceM, lng, lat}] }],
     generatedAt, source: "高德开放平台" }
   ```
   - `count` 取高德返回的总数（不是本页条数）；`items` 取距离最近的前 10 条；无结果时 `count=0`、`nearest=null`。
4. 新增接口 `GET /api/site?address=...`：先地理编码，再统计，返回上面的结构。
5. 首页增加一个地址输入框和“分析”按钮，下方用**表格**展示各类设施的数量和最近距离。暂不做地图和图表。

## 输入 / 输出
- 输入：地址字符串（仅限北京）。
- 输出：`/api/site` 的 JSON 与首页表格。

## 不许改
- `.gitignore`、`.env.example`、`docs/PRD.md`、`lib/llm.ts`。
- 不许读取或打印 `.env.local`；Key 只在服务端使用。
- 统计逻辑里不许调用大模型。

## 硬性约束
- 各类别的编码、半径写成常量放在 `lib/stats.ts` 顶部，方便以后调整。
- 高德接口有调用频率限制：同一次分析里的多个类别请求要依次或限并发发送，遇到频率限制错误时给出明确提示，不许崩溃。
- 空地址、不存在的地址，返回明确的中文错误信息和合适的 HTTP 状态码。
- 每个函数写一行中文注释。

## 验收标准（要有可运行证据）
1. `npm run build` 通过。
2. 用三个不同的北京地址调用 `/api/site`，都在 30 秒内返回；三个地址的结果贴在交付说明里。
3. **抽查核对**：任选一个地址，对每个类别，把“最近设施”的名称与坐标和高德地图网页/App 上的实际位置对照，确认大致吻合；交付说明写明抽查了哪个地址、哪几项。
4. 输入“asdfgh”之类不存在的地址，返回明确提示，页面不崩溃。
5. `git status` 无 `.env.local`；全仓库搜索 Key 前 6 位无结果。
6. 交付说明列出：改动文件、各文件作用、验证方法、以及执行中遇到的问题。
