# 派工单 005：公开部署前的加固

状态：已完成并验收（限流存储选 A：进程内存）

## 背景
在线版公开后，任何人都能调用接口，背后消耗的是作者的高德额度和 DeepSeek 余额。当前代码有四个问题：
1. `/api/report` 接受任意“统计数据”并调用大模型，等于免费的大模型代理，且可通过伪造的设施名称做提示词注入。
2. `/api/health` 每次访问都同时调用高德和 DeepSeek，可被反复刷。
3. 没有频率限制。
4. 没有输入长度限制。

## 要做什么
1. **统计数据签名（`lib/sign.ts`，纯函数 + 单测）**
   - `/api/site` 返回的统计数据附带 `signature` 与 `expiresAt`（签发后 30 分钟过期），使用 HMAC-SHA256，密钥来自环境变量 `SIGNING_SECRET`。
   - 签名前对数据做规范化（键排序），避免 JSON 往返后键顺序不同导致验签失败。
   - `/api/report` 必须验签通过且未过期才处理，否则返回 403 与明确提示；不再信任客户端提交的任何字段。
   - 生产环境（`NODE_ENV=production`）缺少 `SIGNING_SECRET` 时启动即报错；开发环境缺少时使用进程内随机密钥并在控制台提示。
2. **频率限制（`lib/rate-limit.ts`，纯逻辑 + 单测）**
   - 按访问者 IP（取 `x-forwarded-for` 第一个地址）对 `/api/site`、`/api/report` 分别限制：每分钟、每天各一个上限。
   - 另设全站每日总上限，超过后所有访问者收到“今日额度已用完，请明天再试或查看静态演示”的提示。
   - 上限通过环境变量配置，默认值：每 IP 每分钟 6 次、每天 30 次；全站每天 300 次。
   - 超限返回 429，附带中文提示与 `Retry-After`；页面友好展示。
   - 存储方式见文末“待你决定”。
3. **输入清洗（`lib/input.ts`，单测）**：地址去首尾空格，长度 1 到 60 字符，拒绝控制字符与换行；不合规返回 400。
4. **`/api/health` 在生产环境返回 404**（本地开发仍可用）。
5. **基础安全响应头**（`next.config.ts`）：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: DENY`。
6. **页面**：429/403 给出友好提示并指向静态演示页；简报请求失败时不影响已显示的统计表。
7. 更新 `.env.example`（增加 `SIGNING_SECRET`、限流变量，均为空模板）和 README 的相应说明。

## 不许改
- `lib/verify.ts` 及其测试、`lib/stats.ts` 的统计逻辑、`docs/PRD.md`。
- 不许读取或打印 `.env.local`。

## 硬性约束
- 签名与限流逻辑必须是可单测的纯函数，时间通过参数注入，测试里不许用真实等待。
- 每个函数写一行中文注释；错误信息中不得出现密钥。
- 不引入新依赖（使用 Node 自带 `node:crypto`）。

## 验收标准（要有可运行证据）
1. `npm run build` 通过；`npm test` 通过。
2. 单测覆盖：签名有效通过；数据被篡改（改一个数字、改一个设施名）被拒；签名过期被拒；缺少签名被拒；密钥不同被拒；键顺序不同但内容相同仍通过；生产环境缺密钥报错。限流：窗口内超限被拒、窗口滑过后恢复、每日上限、全站总上限、不同 IP 互不影响。输入：空、超长、含换行、正常中文地址。
3. 集成测试（`npm run build` 后 `npm run start`，即生产模式）：
   - 篡改统计数据后 POST `/api/report` 返回 403。
   - 不带签名 POST `/api/report` 返回 403。
   - 用低上限配置连续请求，第 N+1 次返回 429 且带 `Retry-After`。
   - GET `/api/health` 返回 404。
   - 超长地址与含换行地址返回 400。
   - 正常流程（输入地址、统计、简报）仍然成功，简报 `verified=true`。
4. 全仓库搜索 Key 与 `SIGNING_SECRET` 值的前 6 位，无结果；`.env.local` 未入库。
5. 交付说明列出：改动文件、各文件作用、验证方法、遇到的问题，以及**这套加固仍无法防住的情况**。

## 待你决定：限流数据存哪里
- **A. 进程内存（推荐先用）**：不需要任何额外账号。缺点：Vercel 是多个短命实例，每个实例各自计数，限流只是“尽力而为”，防不住有意的攻击。兜底靠：DeepSeek 是预充值制，最坏情况就是余额被用完（几元），高德个人账号有每日额度，超了会自动报错。
- **B. Upstash Redis（免费额度）**：所有实例共享计数，限流可靠。缺点：要多注册一个账号，多两个环境变量。

选 A 的话，本单不引入外部服务，上线后如果发现被滥用，再升级到 B。
