# 派工单 001：项目骨架与两个接口的连通性验证

状态：待用户确认

## 背景
项目还没有任何代码。需要先证明两件事：1）网页项目能在本机跑起来；2）高德接口和 DeepSeek 接口都能被我们的代码调通。这一步不做任何业务功能。

## 要做什么
1. 在项目根目录创建 Next.js（App Router、TypeScript、Tailwind、无 src 目录）项目。
2. 写一个后端接口 `GET /api/health`，做两件事并返回结果：
   - 用高德地理编码接口，把“北京市海淀区清华大学东门”转成经纬度。
   - 用 DeepSeek 发一句“请用一句话回答：1+1 等于几”，取回回答。
3. 首页放一个按钮“测试连接”，点击后调用 `/api/health`，把两个结果显示在页面上；任何一个失败要显示具体原因。

## 输入 / 输出
- 输入：`.env.local` 里的 `AMAP_WEB_KEY`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。
- 输出：能运行的项目；`npm run dev` 后访问 http://localhost:3000 可用。

## 不许改
- `.gitignore`、`.env.example`、`docs/PRD.md`。
- 不许读取或打印 `.env.local` 的内容；Key 只能在服务端代码里通过 `process.env` 使用，不许出现在前端代码、日志或返回结果里。

## 硬性约束
- 大模型调用封装在单独的文件（`lib/llm.ts`），高德调用封装在 `lib/amap.ts`，方便以后替换。
- 每个函数写一行中文注释说明用途。
- 不引入不必要的依赖。

## 验收标准（要有可运行证据）
1. `npm run build` 通过，无报错。
2. 页面点击“测试连接”，显示：一组经纬度（应在北京海淀区附近）+ DeepSeek 的回答。
3. 故意把 Key 改错，页面显示明确的失败原因，不白屏。
4. `git status` 中不出现 `.env.local`；全仓库搜索 Key 的前 6 位，无结果。
5. 执行方在交付时列出：改了哪些文件、每个文件干什么、怎么验证的。

## 完成后
按验收标准逐条核对，再做一次 Git 提交，提交说明写清楚做了什么。
