# PRD v0.1（草稿，待你修改确认）

## 1. 一句话
设计课学生输入北京的一个地址，得到一份带数据来源的场地分析简报，作为课程作业前期调研的起点。

## 2. 目标用户
建筑、城市设计专业的学生（第一个用户：你自己和同学）。

**用户的痛点：** 做场地分析要手动在地图上一个个数周边设施，耗时，且容易漏。

## 3. 第一版（MVP）做什么
1. 输入一个北京的地址或地名（如“北京市海淀区清华大学东门”）。
2. 定位：地址转坐标（高德地理编码）。
3. 以该点为中心，检索 1 km 范围内的设施：交通（地铁、公交）、教育、医疗、商业、公园绿地。
4. 统计各类设施的数量和最近距离。
5. 大模型基于统计数据写一份简报，每条结论标注数据来源；数据不足的地方明确写出“数据不足”。
6. 页面展示：地图上的设施点、统计图表、简报文字。

## 4. 第一版不做什么
- 不做用户登录和历史记录（第 3 周再加）。
- 不做北京以外的城市。
- 不做步行/公交可达性路径分析（后续版本）。
- 不做导出 PDF。

## 5. 验收标准（怎样算做完）
- 输入 3 个不同的北京地址，都能在 30 秒内出结果。
- 简报里的每个数字都能在统计表里找到对应。
- 输入不存在的地址时，页面给出明确提示，不崩溃。
- 仓库里搜索不到任何 Key。

## 6. 技术决策
| 环节 | 选择 | 理由 |
|---|---|---|
| 前后端 | Next.js + Tailwind | 一个项目同时含前端和后端，新手友好 |
| 大模型 | DeepSeek（调用层可替换） | 国内可直接访问，成本低，兼容 OpenAI 格式 |
| 地理数据 | 高德 Web 服务 API | 国内数据全，有免费额度 |
| 部署 | Vercel（第 3 周再定域名） | 免费，链接可写进简历 |

## 7. 已决定
- 简报语气：偏学术（适合课程作业）。
- 检索半径：固定 1 km，后续版本再做可选。
