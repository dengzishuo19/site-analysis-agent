## 1. POI 噪点过滤（用户提出，优先级高）

**✅ 已实现（折叠 + 类别归错剔除 + 度量）：**
- 折叠：`lib/poi-filter.ts`，按 `parent` 把教育、医疗、工业的子点位折叠到所属机构（附属学校、异地分部例外）；校内没有 `parent` 的点位，按“名称以大学/医院名开头”折叠。
- 剔除类别归错：`lib/poi-rules.ts`，培训机构/成人教育/校内设施类型、协会事务所党校行政学院老年大学、药店、在建项目、标为工厂的门店、写字楼里标成“工厂”的公司。
- 度量：`docs/testset/`（5 个场地、389 个点位的人工标注，规则经用户审定）+ `npm run eval:poi`。基线与现状：只按 parent 折叠时误杀 4/184、漏网 48/205；现在误杀 1/184、漏网 16/205。用清华、北大三院、中关村软件园、北师大抽查（未参与调规则），被剔除的点位均判对。
- 地铁、公交、商业、公园不折叠；地铁不截断（地图全部标出）。

**已知局限：**
① 剩余漏网多是名称和类型都看不出问题的点位（如“致真教育”“元玺示范区”），没有通用规则；剩余 1 个误杀是协和的“帅府壹号门诊”（异地门诊点，与院内科室难以区分）。
② 测试集只有 5 个场地，数字不能外推；抽查是人工看的，不是度量。
③ 每类最多取 3 页（75 条）。大校园（如北京大学教育类高德 190 条）折叠后只能标“至少 N”，N 远低于真实值，数量口径需另行处理。
④ 子类型分解与使用者勾选已完成（派工单 009）。

（以下为原始分析）

**问题：**高德把校内的教务处、院系办公室、后勤中心等都归入“教育”类，真实场地分析里这些点位无用且混淆信息。例如搜索“北京建筑大学西城校区”，教育类几乎全是校内点位；国贸的“教育”里也混进培训机构，“工业”里混进服装定制店。

**已验证的事实（008 的探测）：**用关键字搜索取 POI 时（`extensions=all`），校区本身的 `parent` 为空，校内的建筑系、食堂、停车场、招生就业处等的 `parent` 都指向校区的 ID（北京建筑大学样本里完全一致）。008 已用它给候选列表去噪；把同样的做法用到设施统计（周边搜索接口）之前，需要先确认周边搜索返回里也带 `parent` 字段。

**思路（未验证，动手前先用真实数据核对）：**
- 高德 POI 有 `parent` 字段：校内设施的 `parent` 常常指向校园本身。可以把“父级也在同一类别里”的点位视为校内设施，折叠为一个（校园本身）。需要在 `lib/amap.ts` 的检索里带上 `extensions=all`，并核对字段是否真的可靠。
- 按子类型过滤：教育类下有高等院校、中学、小学、幼儿园、培训机构等子类，可以让用户选择或默认只保留“完整教育机构”，把培训机构与校内部门分开。
- 名称规则作为兜底（如以“办公室”“处”“中心”“部”结尾）：容易误伤，只能作为辅助，需要测试集。
- 统计口径要同步：过滤后“数量”“最近设施”“简报”“图表”“地图”的数字必须一致；简报里要如实说明过滤规则，否则“数字能对上统计表”这条验收会被破坏。
- 需要一个人工标注的小测试集（几个典型校园、医院园区、产业园），度量过滤的误杀率与漏网率，而不是凭感觉。

## 2. 地图标记密集时互相遮挡

**✅ 已解决（派工单 012）**：跨类聚合，随缩放重算，18 级以上全部拆开。默认视野下被压住的符号从 15–72 个降到 0–2 个。手机上图例占行多的问题已改为窄屏短名（4–5 行 → 3 行，触控高度仍 44 px）。

市中心（如国贸）同一位置有很多点位，标记重叠。可选：聚合标记、按距离分层、只显示选中类别、标记缩小。
